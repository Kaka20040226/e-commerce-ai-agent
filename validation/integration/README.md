# Agent 集成验证

验证对象为上游提交 `faf0fd8309c550426f3b2cce057dd4566e209e09` 的原始 Python 版。实际执行 FastAPI 路由、Supervisor、LangGraph、四个 Agent、库存决策、A/B 分组和营销词过滤。测试在 `ChatOpenAI.ainvoke` 注入确定性回复、错误和等待，不发出模型请求。候选数据通过替换上游 `MOCK_PRODUCTS` 提供，库存使用商品记录里的设定值。

## 运行结果

CPython 3.13.13 环境下 **19 条测试断言通过**。其中 5 条为上游 A/B 单测，4 条验证了正常链路、模型主动抛出超时后的降级和两个 HTTP 入口，1 条验证了非 JSON 输出的降级并发现成功状态仍为真，9 条用于复现缺陷。后 9 条包含 2 条使用实际商品元数据与模拟库存的复现，部分场景复现了同一缺陷。

| 场景 | 实测结果 |
|---|---|
| 正常推荐 | 画像 Agent 读取请求中的浏览次数。画像的偏好类目进入重排提示，VIP 分群进入营销模板。返回 2 件商品，文案只对应这两件，敏感词“最好”替换为 `***`。库存输出覆盖两级预警和限购。 |
| 部分缺货 | 请求 2 件，排序第一件缺货，输出及文案各 1 条。库存已确认其他候选有货，聚合阶段缺少补位。两个 API 都复现此行为。 |
| 全部缺货 | 库存给出空的可用商品列表，聚合阶段回退到原排序，返回 2 件零库存商品并生成对应文案。 |
| 候选集不一致 | 库存检查 SKU-1 至 SKU-4，个性化重排选出 SKU-5 和 SKU-6。交集为空时两件未经库存检查的商品被输出，并进入营销文案。 |
| 文案商品与价格失真 | 推荐商品是 SKU-2（¥92）和 SKU-1（¥91）。替身返回目录外商品 ID 和 SKU-2 各一条 ¥1 的文案。接口返回 HTTP 200，原样输出两条文案，营销 Agent 标记成功。 |
| 重复重排结果 | 模型返回合法 JSON 数组 `["SKU-2", "SKU-2"]`，最终推荐和营销文案均含两个相同的商品 ID。 |
| 模型请求抛出超时 | 重排调用尝试 2 次，重排结果标记失败，原始候选可用于推荐并生成文案。 |
| Agent 超时阈值 | 将重排 Agent 阈值设为 5 ms，模型替身等待 40 ms 后返回。该调用正常结束且只有 1 次，配置阈值未限制等待。 |
| 模型返回非 JSON | 画像回落到活跃用户，重排回落到候选原顺序，营销文案为空。三个 Agent 的结果仍标记成功。 |
| A/B 策略分发 | `control` 配置为 `rule_based`，`treatment_llm` 配置为 `llm`。两组各调用重排模型 1 次，提示和输出商品完全相同。 |
| 真实商品数据与模拟库存 | REES46 商品元数据走真实 FastAPI 推荐入口。部分缺货输出 1 件和 1 条文案，全部缺货时仍输出 2 件零库存商品和 2 条文案。 |

库存输入与回退集中在 `orchestrator/supervisor.py:82` 至 `orchestrator/supervisor.py:109`。A/B 标签在 `orchestrator/supervisor.py:67` 分配，重排调用在第 85 行。超时存储和重试调用分别见 `agents/base_agent.py:20` 和第 48 至 58 行。`agents/marketing_copy_agent.py:96` 至第 103 行解析文案并过滤敏感词。`agents/product_rec_agent.py:85` 至第 97 行将排序输出映射为商品列表。

额外执行两次无模型替身的启动探测。空环境下导入应用因 SDK 缺少凭证失败。设置本地占位凭证和回环地址后，FastAPI 完成启动，`GET /health` 返回 200。两次探测均未调用模型。

## 复现

从仓库根目录按 [验证指南](../README.md#agent-集成测试) 安装锁定依赖并运行测试。默认运行 17 个测试，用本地 REES46 CSV 或 CSV.GZ 设置 `ECOM_VALIDATION_SAMPLE` 后会额外运行 2 个真实商品场景。

真实商品场景从输入文件中选取前六个类目非空、价格大于零的不同商品。测试合成显示名，使用固定库存值与模型替身。 [REES46 数据集](https://data.rees46.com/datasets/marketplace/2019-Oct.csv.gz)
